Spring 에서 Redis 쓰기

2026년 9월 28일 · 읽는 데 7분
nabong

시리즈Redis

  1. Redis, 개념부터 자료구조와 명령어까지
  2. Redis 컨테이너 접속과 상태 확인
  3. Spring 에서 Redis 쓰기

Redis 가 무엇이고 redis-cli 에서 어떻게 보는지는 앞 글에 적었습니다. 이 글은 Spring 에서 Redis 를 사용하는 방법을 정리했습니다.

의존성과 연결 설정

섹션 제목: “의존성과 연결 설정”

비밀번호를 걸어 둔 Redis 라면 password 를 넣습니다. 설정 파일에 그대로 적지 말고 환경 변수로 받습니다. 빠지면 첫 명령에서 NOAUTH, 틀리면 접속할 때 WRONGPASS 에러가 납니다.

자주 쓰는 항목은 이 정도입니다.

항목 뜻 기본값
host Redis 주소 localhost
port 포트 6379
password 비밀번호 없음
database DB 번호. Redis 하나를 여러 앱이 번호로 나눠 쓸 때 씁니다 (0~15) 0
timeout 명령 하나의 응답을 기다리는 시간 60초
connect-timeout 처음 연결을 맺을 때까지 기다리는 시간 10초

timeout 을 적지 않으면 60초입니다. Redis 가 멈추면 요청도 그 시간 동안 같이 기다립니다. 짧게 잡으면 문제가 생겼을 때 빨리 실패하는 대신, 원래 오래 걸리는 명령도 도중에 실패할 수 있습니다. 앱에서 쓰는 명령이 얼마나 걸리는지 보고 정합니다. 단위 없이 3000 으로 적으면 밀리초로 읽힙니다.

Spring Boot 2.x 에서는 spring.redis.host 였습니다. 3.x 에서 spring.data.redis.host 로 바뀌었습니다. 예전 설정이 남아 있으면 값이 적용되지 않고 localhost:6379 로 접속하려다 실패합니다.

스타터를 넣으면 StringRedisTemplate 이 자동으로 만들어집니다. 주입해서 씁니다.

opsForXxx 와 Redis 자료구조

섹션 제목: “opsForXxx 와 Redis 자료구조”

RedisTemplate 과 opsForXxx() 는 Redis 가 아니라 Spring Data Redis 가 정한 이름입니다. Redis 가 정한 것은 SET, HSET 같은 명령뿐이고, 명령을 실제로 보내는 일은 그 아래의 드라이버인 Lettuce(Spring Boot 기본값)가 합니다. Spring Data Redis 는 그 위에서 연결과 직렬화를 맡고, 명령을 자료구조별로 묶어 메서드로 내놓습니다.

메서드 돌려주는 것 Redis 자료구조
opsForValue() ValueOperations String
opsForHash() HashOperations Hash
opsForList() ListOperations List
opsForSet() SetOperations Set
opsForZSet() ZSetOperations Sorted Set

첫 줄이 헷갈리는 지점입니다. Redis 의 String 자료구조를 Spring 에서는 Value 라는 이름으로 씁니다. 나머지는 이름이 같습니다.

DEL, EXPIRE, TYPE 처럼 자료구조와 상관없이 키에 거는 명령은 redis.delete(), redis.expire() 처럼 템플릿에 바로 있습니다.

opsForXxx() 결과는 매번 이어 붙여 써도 됩니다. 다만 opsForHash() 는 이어 붙이면 필드와 값의 타입이 Object 로 잡힙니다. 타입을 받는 쪽 변수에서 정하는데, 이어 붙이면 받는 변수가 없기 때문입니다.

변수로 한 번 받아 두면 타입이 정해집니다.

나머지 opsForValue(), opsForList() 등은 템플릿의 타입을 그대로 쓰기 때문에 이어 붙여도 형변환이 필요 없습니다.

직렬화

섹션 제목: “직렬화”

StringRedisTemplate 대신 RedisTemplate 을 그대로 주입해 쓰면 redis-cli 에서 키와 값을 알아볼 수 없게 됩니다.

redis-cli 로 꺼내면 이렇게 나옵니다.

키 이름부터 알아볼 수 없습니다.

RedisTemplate 의 기본 직렬화가 JDK 직렬화라서 그렇습니다. 자바 객체를 바이트로 바꿔 넣기 때문에 자바 밖에서는 읽을 수도, 같은 키로 찾을 수도 없습니다.

StringRedisTemplate 을 쓰면 키와 값을 그대로 문자열로 넣습니다.

객체를 통째로 넣어야 하면 JSON 으로 직렬화해서 문자열로 넣습니다. 그러면 redis-cli 에서도 읽힙니다.

문자열로 넣어 두면 redis-cli 나 GUI 도구에서 값을 바로 읽을 수 있습니다. 세션 같은 값이 잘못 들어갔는지 확인할 때 필요한 일입니다. JDK 직렬화로 넣은 값은 자바 코드를 거쳐야만 읽을 수 있습니다.

String

섹션 제목: “String”

increment 는 저장된 숫자를 올리고 올린 뒤의 값을 돌려줍니다. 날짜별 방문 수를 센다고 하면 이렇게 됩니다.

키가 없으면 0 에서 시작합니다. 두 번째 인자를 주면 그만큼 올립니다. 돌려주는 값은 Long 이고, Redis 에는 문자열로 저장됩니다.

숫자가 아닌 값이 들어 있는 키에 호출하면 에러가 납니다. "user=1000" 이 들어 있는 session:a1b2c3 에 increment 를 호출하는 경우입니다.

Hash

섹션 제목: “Hash”

HashOperations<H, HK, HV> 는 타입 인자가 셋입니다. 키 타입, 필드 타입, 값 타입 순입니다.

List

섹션 제목: “List”

최근 목록을 만들 때는 넣고 바로 자릅니다.

Set

섹션 제목: “Set”

들어 있는지 확인하는 방법은 두 가지인데, 원소가 많아지면 차이가 커집니다.

isMember 는 원소가 10개든 100만 개든 걸리는 시간이 거의 같습니다. Set 은 안에서 값으로 바로 찾아가는 구조라 처음부터 하나씩 훑지 않습니다. members 로 받아오면 원소가 100만 개일 때 100만 개를 네트워크로 받은 다음에야 찾기 시작합니다.

Sorted Set

섹션 제목: “Sorted Set”

reverseRange 는 값만, reverseRangeWithScores 는 점수까지 같이 줍니다. 순위표를 만들 때는 점수도 보여줘야 하니 대개 뒤쪽을 씁니다.

만료

섹션 제목: “만료”

getExpire 가 -1 이면 만료가 없는 키, -2 면 키가 없는 것입니다.

값을 넣을 때 같이 거는 편이 안전합니다. set 하고 expire 를 따로 호출하면 그 사이에 예외가 나거나 프로세스가 죽었을 때 만료 없는 키가 남습니다.

값을 고칠 때 만료가 어떻게 되는지는 자료구조마다 다릅니다. String 을 set 으로 덮어쓰면 걸려 있던 만료가 지워집니다. 만료를 유지하려면 덮어쓸 때도 만료를 같이 줍니다.

Hash 의 필드를 put 으로 고치는 것은 키의 만료에 영향을 주지 않습니다. 걸어 둔 만료 시각이 그대로 유지됩니다.

키 조회

섹션 제목: “키 조회”

redis.keys() 는 이름만 보면 평범한 메서드지만 KEYS 명령을 그대로 보냅니다. KEYS 는 패턴에 맞는 키만이 아니라 DB 의 키 전체를 훑고, 그동안 Redis 가 다른 명령을 처리하지 못합니다. 개념 글에서 KEYS * 는 운영에서 쓰지 않는다고 했는데, session:* 처럼 패턴을 붙여도 훑는 범위는 같습니다. 이유는 개념 글의 명령을 한 줄로 세워 하나씩 처리합니다에 있습니다.

앱 코드에서는 키를 찾을 일이 거의 없습니다. ID 를 알고 있으니 키를 만들어서 바로 꺼냅니다. 목록이 필요하면 키를 찾지 말고, 저장할 때 목록도 같이 저장합니다. 접속 중인 세션 목록이 필요하다면 이렇게 합니다.

목록은 sessions:active 하나만 읽으면 됩니다. 같은 Redis 에 다른 키가 얼마나 많든 상관없습니다.

다만 Set 의 원소에는 만료가 없습니다. 세션 키가 30분 뒤 만료로 사라져도 sessions:active 에는 ID 가 남습니다. 목록을 읽을 때 세션 키가 없는 ID 를 Set 에서 빼 주거나, 주기적으로 정리합니다.

운영 중에 키를 확인하거나 옛 키를 한꺼번에 정리할 때처럼 가끔 훑어야 하면 scan() 을 씁니다. 조금씩 나눠 가져와서 Redis 를 멈추지 않습니다.

Cursor 는 다 쓰면 닫아야 커넥션이 풀립니다.

동시 수정

섹션 제목: “동시 수정”

숫자를 올릴 때는 get 으로 읽어 set 으로 다시 쓰지 말고 increment 를 씁니다. 서버가 여러 대면 앞의 방식은 값이 틀어집니다.

increment 없이 방문 수를 1 올리는 코드를 짜면 이렇게 됩니다. 쓰면 안 되는 방식입니다.

서버 한 대에서는 문제가 없습니다. 서버 두 대가 동시에 이 코드를 돌리면 이렇게 됩니다.

순서 서버 A 서버 B Redis 값
1 get → 10 10
2 get → 10 10
3 set 11 11
4 set 11 11

두 번 올렸는데 11 입니다. 둘 다 10 을 읽은 다음에 썼기 때문입니다.

increment 는 읽고, 더하고, 쓰는 것을 Redis 안에서 명령 하나로 합니다. Redis 는 명령을 하나씩 처리하므로 두 서버의 increment 사이에 끼어들 틈이 없고, 결과는 12 가 됩니다.

객체를 JSON 문자열 하나로 넣어 두고 get 해서 필드를 고친 뒤 set 하는 것도 같은 문제입니다. 한 서버가 고친 필드를 다른 서버가 옛 값으로 덮어씁니다. 필드를 따로 고치는 객체라면 Hash 로 넣고 opsForHash().put() 으로 그 필드만 씁니다. 개념 글의 JSON 문자열로 넣을까, 자료구조를 쓸까에 그림으로 있습니다.

JSON 안에 들어 있는 숫자는 increment 를 쓸 수 없습니다. 설정을 JSON 한 덩어리로 저장하면서, 저장할 때마다 버전을 1 올리는 경우입니다.

Redis 에게 이 값은 숫자가 아니라 문자열 한 덩어리라서 increment 가 버전 필드만 올릴 수 없습니다. 두 사람이 같은 설정을 거의 동시에 저장하면 위 표와 같은 일이 생깁니다. 둘 다 버전 5 를 읽고 6 을 씁니다. 게다가 나중에 저장한 쪽의 JSON 이 먼저 저장한 쪽 내용을 통째로 덮어씁니다. 한 사람이 고친 내용이 사라지는데, 버전은 한 번만 올라서 두 번 저장됐다는 흔적도 남지 않습니다.

막으려면 화면이 읽어 간 버전을 저장 요청에 같이 보내고, 저장하기 전에 지금 버전과 비교합니다. 다르면 그 사이에 누가 먼저 저장한 것이니 거절합니다. 이 방식을 낙관적 잠금이라고 합니다.

이렇게 해도 비교와 set 사이에 아주 짧은 틈이 남습니다. 두 요청이 동시에 비교를 통과하면 여전히 한쪽이 덮어씁니다. 그 틈까지 막으려면 비교와 저장을 Redis 안에서 한 번에 해야 합니다. WATCH 로 키를 지켜보다가 그 사이 바뀌었으면 저장을 취소하거나, Lua 스크립트로 비교와 저장을 명령 하나처럼 실행합니다. 관리자 화면처럼 동시에 저장하는 일이 드물면 위의 비교만으로도 대부분 충분합니다.

redis-cli 명령과 메서드 대응

섹션 제목: “redis-cli 명령과 메서드 대응”
하려는 것 redis-cli Java
값 넣기 SET k v opsForValue().set(k, v)
만료까지 같이 SET k v EX 1800 opsForValue().set(k, v, Duration.ofMinutes(30))
값 꺼내기 GET k opsForValue().get(k)
숫자 올리기 INCR k opsForValue().increment(k)
객체 필드 넣기 HSET k f v opsForHash().put(k, f, v)
객체 전체 꺼내기 HGETALL k opsForHash().entries(k)
목록에 넣기 RPUSH k v opsForList().rightPush(k, v)
목록 잘라 보기 LRANGE k 0 9 opsForList().range(k, 0, 9)
목록 길이 제한 LTRIM k 0 9 opsForList().trim(k, 0, 9)
모음에 넣기 SADD k v opsForSet().add(k, v)
들어 있나 SISMEMBER k v opsForSet().isMember(k, v)
점수와 함께 넣기 ZADD k 120 v opsForZSet().add(k, v, 120)
상위 10개 ZREVRANGE k 0 9 opsForZSet().reverseRange(k, 0, 9)
만료 걸기 EXPIRE k 1800 expire(k, Duration.ofMinutes(30))
남은 시간 TTL k getExpire(k, TimeUnit.SECONDS)
지우기 DEL k delete(k)
자료구조 확인 TYPE k type(k)
키 찾기 SCAN 0 MATCH k* scan(ScanOptions)
