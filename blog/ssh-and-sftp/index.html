서버에 접속하고 파일 주고받기

2026년 9월 22일 · 읽는 데 3분
nabong

서버가 무엇이고 그 안에서 어떤 명령을 쓰는지는 터미널 글에 적었습니다. 이 글은 그 앞뒤에 붙는 것입니다. 무엇으로 접속하는지, 그리고 파일을 어떻게 주고받는지.

터미널과 ssh 는 다른 층

섹션 제목: “터미널과 ssh 는 다른 층”

터미널은 문자로 명령을 주고받는 창입니다. ssh 는 그 창에서 실행하는 명령입니다.

터미널을 고르는 것과 서버에 접속하는 것은 다른 일입니다. 이게 갈리지 않으면 “터미널을 설치한다” 와 “서버에 접속한다” 가 한 덩어리로 뭉칩니다.

윈도우에도 ssh 가 이미 있습니다

섹션 제목: “윈도우에도 ssh 가 이미 있습니다”

PowerShell 을 열고 바로 입력하면 됩니다.

Windows 10 1809 부터 OpenSSH 클라이언트가 기본 포함입니다. mac 과 리눅스는 원래 기본 터미널에 들어 있습니다. 아무것도 설치하지 않고 시작할 수 있습니다.

처음이라면 여기서 시작하는 게 낫습니다. 클라이언트를 고르는 일과 접속이 되는지 확인하는 일을 섞지 않게 됩니다.

그래도 전용 클라이언트를 쓰는 이유

섹션 제목: “그래도 전용 클라이언트를 쓰는 이유”

네 가지입니다.
접속 정보 저장 서버가 늘어나면 IP 와 계정을 매번 치기 어렵습니다
탭 서버 여러 개를 창 하나에서
키 관리 개인키 파일 경로를 등록해 두고 고릅니다
파일 전송 터미널과 SFTP 를 같은 창에서

저는 Termius 를 씁니다. 접속 정보 등록 화면이 잘 되어 있고, 서버 파일을 드래그로 주고받는 게 편해서입니다. Windows·mac·Linux 판이 있고 무료로도 씁니다.

다른 선택지도 적어 둡니다.

  • XShell + XFtp — 국내에서 쓰는 곳이 많습니다. 터미널과 파일 전송이 별도 프로그램이고, 가정·학교용 무료 라이선스가 있습니다
  • MobaXterm — SSH 세션을 열면 왼쪽에 SFTP 브라우저가 같이 뜹니다
  • PuTTY — 오래된 표준. 기능은 적지만 용량이 작고 어디에나 있습니다
  • VS Code Remote-SSH — 서버 파일을 에디터에서 바로 열어 고칩니다. 편집이 주 목적이면 이쪽입니다

등록할 때 채우는 칸

섹션 제목: “등록할 때 채우는 칸”

클라이언트마다 메뉴 이름은 다르지만 채우는 칸은 같습니다.

칸 넣는 것
Host, Address 서버 IP 나 도메인
Port 22. 바꾼 서버면 그 번호
Username 로그인할 계정
Password, Key 인증 방식. 키를 쓰면 개인키 파일을 지정합니다
Label, Name 목록에 보일 이름

한 번 저장해 두면 목록에서 고르는 것으로 접속이 끝납니다. 서버가 열 개를 넘어가면 이것만으로도 클라이언트를 쓸 값이 됩니다.

파일 주고받기

섹션 제목: “파일 주고받기”

서버에 jar 를 올리거나 로그를 내려받을 때 필요합니다.

SFTP 는 SSH 위에서 도는 파일 전송입니다. SSH 접속이 되면 대개 별도 설정 없이 됩니다. 서버에 따로 띄워야 하는 서비스가 없습니다.

이름이 닮은 FTP 와는 다른 것입니다. FTP 는 암호화가 없고, 서버에 FTP 서비스를 별도로 설치해 띄워야 합니다.

scp — 한 번 복사하고 끝

섹션 제목: “scp — 한 번 복사하고 끝”

secure copy 입니다.

콜론 뒤가 서버 쪽 경로입니다. 콜론을 빼면 그냥 로컬 파일 복사가 되니 빠뜨리지 않게 봅니다.

맨 끝의 . 은 현재 폴더라는 뜻입니다. 받을 위치를 적는 자리라서 생략할 수 없습니다.

sftp — 접속해서 돌아다니며

섹션 제목: “sftp — 접속해서 돌아다니며”

앞에 l 이 붙은 것은 내 PC 쪽 명령입니다. local 의 l 입니다. 어느 쪽 파일을 보고 있는지 헷갈릴 때 pwd 와 lpwd 를 나란히 실행해 보면 됩니다.

어느 것을 쓰나

섹션 제목: “어느 것을 쓰나”
상황
파일 몇 개 옮기기 클라이언트의 SFTP 화면에서 드래그가 빠릅니다
스크립트에 넣기 scp. 한 줄로 끝나고 결과가 종료 코드로 나옵니다
큰 파일을 반복해서 rsync. 바뀐 부분만 전송합니다
서버 안에서 옮기기 접속해서 cp 나 mv. 내 PC 를 거칠 이유가 없습니다

권한 때문에 막힐 때

섹션 제목: “권한 때문에 막힐 때”

올린 파일이 보이지 않거나 지울 수 없으면 대개 권한 문제입니다.

scp 와 sftp 는 접속한 계정의 권한으로 파일을 씁니다. dev 계정으로 접속했다면 dev 가 쓸 수 있는 곳에만 올라갑니다. 그 폴더가 root 소유라면 막힙니다.

두 가지 방법이 있습니다. 홈 디렉터리 같은 쓸 수 있는 곳에 올린 뒤 서버에서 sudo mv 로 옮기거나, 그 폴더의 소유자를 dev 로 바꿔 두는 것입니다.

권한 표기를 읽는 법은 터미널 글의 계정과 권한에 적었습니다.

명령어 한눈에

섹션 제목: “명령어 한눈에”
하려는 것 명령 이름의 뜻
접속 ssh dev@서버 secure shell
포트가 다를 때 ssh -p 2222 dev@서버 port
키를 지정해서 ssh -i ~/.ssh/id_rsa dev@서버 identity
파일 올리기 scp 파일 dev@서버:/경로/ secure copy
파일 내리기 scp dev@서버:/경로/파일 . secure copy
폴더째로 scp -r 폴더 dev@서버:/경로/ recursive
접속해서 주고받기 sftp dev@서버 ssh file transfer protocol
바뀐 것만 보내기 rsync -av 폴더/ dev@서버:/경로/ archive, verbose
태그:
  • 인프라
  • Linux
터미널, 서버 구조부터 vi 까지
도커, 개념부터 Dockerfile 작성까지

함께 읽을 글

터미널, 서버 구조부터 vi 까지서버가 무엇이고 SSH 세션은 왜 끊기면 프로그램까지 죽는지, 리눅스 디렉터리는 어떻게 생겼는지, 그리고 vi 의 모드 셋을 정리했습니다.
Nginx, HTTPS부터 WebSocket 프록시까지Nginx 를 서버에 올릴 때 더하는 설정입니다. HTTPS 와 http 요청 넘기기, 화면 파일 캐시, gzip 압축, WebSocket 과 SSE 프록시, 프록시 타임아웃, 설정 파일 위치를 정리했습니다.
Nginx, 정적 파일부터 API 프록시까지프론트엔드와 백엔드를 나누면 화면 파일을 내보내는 일과 API 요청을 넘기는 일을 누가 맡는지, 로컬 개발과 서버에서 각각 어떻게 동작하는지, 그 일을 Nginx 로 설정하는 방법을 정리했습니다.
