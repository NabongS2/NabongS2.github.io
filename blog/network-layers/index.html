네트워크 계층

2026년 10월 22일 · 읽는 데 5분
nabong

시리즈네트워크 기초

  3. NAT 와 포트포워딩
  4. VPN
  5. DNS 와 도메인
  6. HTTPS 와 인증서

브라우저에 주소를 입력하면 요청은 여러 단계를 거쳐 서버에 도착합니다. 이 글에서는 그 단계를 계층으로 나눠 보는 방법과 각 계층이 하는 일을 알아봅니다. 이 내용은 이어지는 글에서 IP 주소, 포트, NAT, HTTPS 가 각각 어느 계층에 속하는지 설명하는 바탕이 됩니다.

계층으로 나누는 이유

섹션 제목: “계층으로 나누는 이유”

네트워크 통신에는 여러 일이 함께 필요합니다. 주고받는 내용의 형식을 정하고, 받을 프로그램을 찾고, 받을 컴퓨터까지 경로를 찾고, 실제 신호로 전송해야 합니다. 이 일들을 계층으로 나누면 각 계층은 자기 일만 하고, 바로 아래 계층에 전달을 맡깁니다.

계층이 나뉘어 있으면 한 계층을 바꿔도 다른 계층은 그대로입니다. 노트북을 유선 랜에서 Wi-Fi 로 바꿔도 브라우저가 보내는 HTTP 요청은 달라지지 않습니다. 실제 전송 방식은 가장 아래 계층의 일이기 때문입니다.

TCP/IP 4계층

섹션 제목: “TCP/IP 4계층”

인터넷에서 실제로 쓰는 구조는 TCP/IP 4계층입니다. 위 계층부터 정리하면 다음과 같습니다.

계층 하는 일 쓰는 주소 예
응용 프로그램끼리 주고받는 내용의 형식 URL, 도메인 HTTP, DNS, SSH
전송 받을 프로그램을 찾고, 전달 방식을 정함 포트 TCP, UDP
인터넷 받을 컴퓨터를 찾고, 거쳐 갈 경로를 정함 IP 주소 IP
네트워크 접근 같은 네트워크 안에서 실제로 전송 MAC 주소 이더넷, Wi-Fi

요청을 보내는 쪽에서는 데이터가 응용 계층에서 네트워크 접근 계층으로 내려가고, 받는 쪽에서는 반대로 올라갑니다. 중간의 라우터는 받을 컴퓨터를 찾는 인터넷 계층까지만 처리합니다.

네트워크 접근 계층

섹션 제목: “네트워크 접근 계층”

네트워크 접근 계층은 같은 네트워크 안의 장비끼리 데이터를 실제로 전송합니다. 여기서 쓰는 주소가 MAC 주소입니다. MAC 주소는 랜 카드나 Wi-Fi 칩마다 부여된 고유 번호이고, a4:5e:60:12:34:56 처럼 적습니다.

MAC 주소는 같은 네트워크 안에서만 쓰입니다. 다른 네트워크로 넘어갈 때는 라우터가 다음 구간의 MAC 주소로 바꿔 보냅니다.

인터넷 계층

섹션 제목: “인터넷 계층”

인터넷 계층은 받을 컴퓨터의 IP 주소를 보고 데이터를 전달합니다. 목적지가 다른 네트워크에 있으면, 라우터가 목적지 IP 를 보고 다음 라우터로 넘기는 일을 반복해 목적지까지 보냅니다. 공인 IP 와 사설 IP, NAT 가 이 계층의 내용입니다.

전송 계층

섹션 제목: “전송 계층”

전송 계층은 컴퓨터에 도착한 데이터를 포트 번호로 받을 프로그램에 전달합니다. 전달 방식은 TCP 와 UDP 중에서 고릅니다.

TCP UDP
연결 보내기 전에 서로 연결을 맺습니다 연결 없이 바로 보냅니다
도착 확인 받았는지 확인하고, 빠진 것은 다시 보냅니다 확인하지 않습니다
순서 보낸 순서대로 전달합니다 순서를 보장하지 않습니다
쓰는 곳 HTTP(1.1, 2), SSH, DB 접속 DNS 조회, 영상 통화, 게임

TCP 는 빠짐없이 순서대로 전달하는 대신 확인하는 과정만큼 느립니다. UDP 는 데이터 일부가 빠질 수 있는 대신 빠릅니다. 영상 통화는 늦게 도착한 화면을 다시 받는 것보다 다음 화면을 보여 주는 편이 중요해서 UDP 를 씁니다. HTTP/3 는 UDP 위에 확인과 순서 처리를 직접 구현한 QUIC 를 씁니다.

응용 계층

섹션 제목: “응용 계층”

응용 계층은 프로그램끼리 주고받는 내용의 형식을 정합니다. 브라우저와 웹 서버는 HTTP, 터미널과 서버는 SSH, 도메인을 IP 로 바꿀 때는 DNS 를 씁니다.

TLS(Transport Layer Security)는 주고받는 데이터를 암호화하고, 접속한 서버가 진짜인지 인증서로 확인하는 규칙입니다. HTTP 를 TLS 로 감싸 보내는 것이 HTTPS 입니다. TLS 는 응용 계층과 전송 계층 사이에서 동작합니다. HTTP 내용을 TLS 가 암호화한 뒤 TCP 로 보냅니다. TCP/IP 4계층으로 나눌 때는 보통 응용 계층에 포함해 설명합니다.

OSI 7계층

섹션 제목: “OSI 7계층”

OSI 7계층은 같은 내용을 일곱 단계로 더 잘게 나눈 기준 모델입니다. 실제 인터넷은 TCP/IP 구조로 동작하지만, 장비와 기술을 설명할 때는 OSI 의 계층 번호를 자주 씁니다.

OSI 계층 번호 TCP/IP 계층
응용 7 응용
표현 6 응용
세션 5 응용
전송 4 전송
네트워크 3 인터넷
데이터 링크 2 네트워크 접근
물리 1 네트워크 접근

“L4 로드 밸런서”, “L7 로드 밸런서”, “L3 스위치” 처럼 장비 이름에 붙는 숫자가 이 번호입니다. L4 는 IP 와 포트까지 보고 판단하고, L7 은 HTTP 경로와 헤더까지 보고 판단한다는 뜻입니다.

캡슐화

섹션 제목: “캡슐화”

데이터를 보낼 때는 위 계층에서 아래 계층으로 내려가면서, 각 계층이 자기 정보를 담은 헤더를 앞에 붙입니다. 이것을 캡슐화라고 합니다. 받는 쪽은 반대로 아래 계층부터 헤더를 하나씩 제거하며 위 계층으로 전달합니다.

내부 PC(192.168.0.31)가 https://example.com/api/users 를 요청할 때 각 계층이 붙이는 정보는 다음과 같습니다.

계층 붙이는 정보 이 단계의 데이터 이름
응용 GET /api/users, Host: example.com 같은 HTTP 요청 메시지
전송 출발지 포트 51000, 목적지 포트 443 세그먼트
인터넷 출발지 IP 192.168.0.31, 목적지 IP 198.51.100.10 패킷
네트워크 접근 출발지 MAC, 다음 장비의 MAC 프레임

HTTPS 에서는 HTTP 요청 부분이 TLS 로 암호화된 채 TCP 헤더 뒤에 담깁니다. 중간 장비는 IP 와 포트는 볼 수 있지만 요청 경로나 내용은 읽을 수 없습니다.

중간 장비는 자기가 맡은 계층의 헤더까지만 읽습니다. 라우터는 IP 헤더를 보고 다음 경로를 정하고, 그 위의 HTTP 내용은 읽지 않습니다. 반면 Nginx 같은 리버스 프록시는 HTTP 헤더와 경로까지 읽어서 어디로 보낼지 정합니다.

장비와 도구가 동작하는 계층

섹션 제목: “장비와 도구가 동작하는 계층”
장비·도구 보는 정보 계층
스위치 MAC 주소 2
라우터 IP 주소 3
공유기의 NAT, 포트포워딩, Docker -p IP 주소, 포트 3, 4
일반 방화벽 IP 주소, 포트 3, 4
L4 로드 밸런서 IP 주소, 포트 4
Nginx 리버스 프록시, L7 로드 밸런서 HTTP 경로, 헤더 7
웹 방화벽(WAF) HTTP 요청 내용 7

접속되지 않을 때도 아래 계층부터 확인하면 원인 범위를 좁힐 수 있습니다.

확인 명령 확인하는 계층 성공하면 알 수 있는 것
ping 192.168.0.20 인터넷 그 IP 까지 데이터가 도달합니다
nc -zv 192.168.0.20 8080 전송 그 포트에서 프로그램이 기다리고 있습니다
curl http://192.168.0.20:8080/ 응용 서버가 HTTP 로 응답합니다

ping 은 방화벽이 막아 두는 경우가 많아서, ping 이 실패해도 그 위 계층의 접속은 성공할 수 있습니다. 이때는 nc 나 curl 로 다시 확인합니다.
