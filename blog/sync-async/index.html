동기와 비동기

2026년 10월 13일 · 읽는 데 5분
nabong

시리즈API 데이터 다루기

  1. 동기와 비동기
  2. fetch 와 axios
  3. Zustand 와 React Query

동기와 비동기는 파일 읽기, 데이터베이스 조회, 서버 요청처럼 기다리는 시간이 있는 작업이면 어떤 언어에서나 나오는 개념입니다. 자바스크립트 코드에서 fetch, axios, React Query 를 쓰면 나오는 async, await, then 도 모두 이 기다리는 시간을 다루는 방법입니다.

이 글은 그중 브라우저의 자바스크립트에서 동기와 비동기가 어떻게 다르고, 비동기 코드를 어떻게 쓰는지 보고자 합니다.

동기와 비동기

섹션 제목: “동기와 비동기”

동기는 앞의 작업이 끝나야 다음 작업을 시작하는 실행 방식입니다. 코드가 한 줄씩 위에서 아래로 실행되고, 한 줄이 끝나기 전에는 다음 줄로 넘어가지 않습니다.

비동기는 시간이 걸리는 작업을 시작만 해 두고, 끝나기를 기다리지 않고 다음 작업을 실행하는 방식입니다. 작업이 끝나면 그때 결과를 받아 이어서 처리합니다.

setTimeout 은 1초를 기다리는 동안 멈춰 있지 않습니다. 1초 뒤에 실행할 함수를 맡겨 두고 바로 다음 줄로 넘어가서 2 를 먼저 출력합니다.

브라우저에서 비동기가 필요한 이유

섹션 제목: “브라우저에서 비동기가 필요한 이유”

브라우저에서 자바스크립트는 한 번에 한 가지 일만 합니다. 이 하나의 실행 흐름이 코드 실행, 화면 그리기, 클릭과 스크롤 처리를 모두 맡습니다.

그래서 시간이 걸리는 작업을 동기로 기다리면 그동안 페이지 전체가 멈춥니다. 아래 코드는 3초 동안 아무것도 하지 않고 반복문만 돕니다.

서버 요청이 이렇게 동작한다면 응답을 기다리는 동안 페이지가 굳습니다. 그래서 fetch 같은 네트워크 요청과 setTimeout 같은 타이머는 비동기로 동작합니다. 기다리는 일은 브라우저에 맡기고, 자바스크립트는 그동안 다른 일을 계속합니다.

콜백

섹션 제목: “콜백”

비동기 작업이 끝난 뒤에 실행할 일을 함수로 넘겨 두는 방식을 콜백이라고 합니다. 위의 setTimeout 에 넘긴 함수가 콜백입니다.

콜백만으로 순서가 있는 비동기 작업을 이어 쓰면, 작업이 끝날 때마다 다음 콜백을 안쪽에 넣어야 해서 코드가 계속 안으로 들어갑니다. 에러 처리도 단계마다 따로 해야 합니다. 이 문제를 줄이려고 나온 것이 Promise 입니다.

Promise

섹션 제목: “Promise”

Promise 는 “약속”이라는 뜻으로, 비동기 작업의 결과를 나중에 받을 수 있게 해 주는 객체입니다. 지금은 결과가 없지만 나중에 주겠다는 약속을 먼저 돌려준다는 의미입니다. 비동기 함수는 결과를 바로 줄 수 없으니, 대신 Promise 를 바로 돌려줍니다.

이 글의 예시는 블로그의 글(post) 목록을 돌려주는 서버 주소 /api/posts 에 요청을 보낸다고 가정합니다. fetch 는 브라우저에 기본으로 있는, 서버에 요청을 보내는 함수입니다.

상태

섹션 제목: “상태”

Promise 는 세 가지 상태 중 하나입니다.

상태 뜻
대기(pending) 작업이 아직 끝나지 않음
성공(fulfilled) 작업이 끝나고 결과 값이 있음
실패(rejected) 작업이 실패하고 에러가 있음

대기에서 성공이나 실패로 한 번 바뀌면 그 뒤로는 바뀌지 않습니다.

then 과 catch

섹션 제목: “then 과 catch”

결과는 then 에, 에러는 catch 에 함수를 넘겨서 받습니다.

  • then 에 넘긴 함수는 Promise 가 성공하면 결과 값을 받아 실행됩니다.
  • then 은 다시 Promise 를 돌려주기 때문에 이어서 쓸 수 있습니다. 앞의 then 이 돌려준 값이 다음 then 으로 넘어갑니다. 돌려준 값이 Promise 면 그 Promise 가 끝날 때까지 기다렸다가 결과 값을 넘깁니다.
  • res, posts 는 함수의 매개변수 이름이라 다른 이름을 써도 됩니다. res 와 res.json() 이 무엇인지는 fetch 와 axios 글에서 다룹니다.
  • 중간 어디서든 실패하면 남은 then 을 건너뛰고 catch 로 갑니다.

콜백과 달리 순서가 있는 작업이 위에서 아래로 이어지고, 에러 처리는 catch 한 곳에서 합니다.

async 와 await

섹션 제목: “async 와 await”

async 와 await 는 Promise 를 쓰는 코드를 동기 코드처럼 위에서 아래로 읽히게 쓰는 문법입니다. async 는 asynchronous(비동기)를 줄인 말로, 함수 앞에 붙여 비동기 함수라고 표시합니다. await 는 “기다리다”라는 뜻입니다.

  • await 는 Promise 가 성공할 때까지 기다렸다가 결과 값을 꺼냅니다. res 에는 Promise 가 아니라 응답 객체가 들어갑니다.
  • async 함수는 항상 Promise 를 돌려줍니다. return posts 는 posts 로 성공하는 Promise 가 됩니다.

결과를 꺼내는 방법

섹션 제목: “결과를 꺼내는 방법”

fetch 처럼 Promise 를 돌려주는 함수의 결과는 await 나 then 중 하나로 꺼냅니다.

둘 다 쓰지 않으면 결과 대신 Promise 가 그대로 남습니다. 요청은 서버로 가지만, 응답을 쓸 수 없고 실패해도 try...catch 로 잡을 수 없습니다.

async 와 await 의 관계

섹션 제목: “async 와 await 의 관계”
관계 규칙
await 를 쓰는 함수 async 가 필요함. 없으면 문법 에러. 모듈 파일의 최상위 코드에서는 async 없이 쓸 수 있음
async 함수 안의 await 쓰지 않아도 됨

async 함수는 await 가 없어도 Promise 를 돌려줍니다. 하지만 async 는 함수 안에서 await 를 쓰기 위해 붙이는 것이라, await 가 없는 함수에는 붙이지 않습니다.

async 함수 안과 밖

섹션 제목: “async 함수 안과 밖”

async 함수는 밖에서 보면 비동기이고, 안에서는 동기처럼 동작합니다.

  • 안: await 를 만나면 결과가 올 때까지 기다렸다가 다음 줄로 넘어갑니다. 한 줄씩 차례로 실행되는 동기 코드처럼 읽힙니다.
  • 밖: 함수를 호출한 쪽은 기다리지 않고 바로 다음 줄로 넘어갑니다.

그래서 await 로 기다리는 동안에도 페이지는 멈추지 않고, 클릭과 화면 그리기를 계속 처리합니다.

에러 처리

섹션 제목: “에러 처리”

await 한 Promise 가 실패하면 그 줄에서 에러가 던져집니다. 동기 코드와 같은 try...catch 로 받습니다.

여러 요청 함께 보내기

섹션 제목: “여러 요청 함께 보내기”

서로 관계없는 요청 두 개를 보낼 때, 하나씩 await 하면 앞의 응답이 올 때까지 다음 요청을 보내지 않습니다.

Promise.all 은 Promise 여러 개를 받아, 모두 성공하면 결과를 배열로 돌려주는 Promise 를 만듭니다. 요청을 먼저 모두 보내 두고 한꺼번에 기다리므로, 결국 기다리는 것은 가장 오래 걸리는 요청 하나입니다.

  • 하나라도 실패하면 Promise.all 은 바로 실패합니다. 실패한 요청이 있어도 나머지 결과를 받고 싶으면 Promise.allSettled 를 씁니다. 결과마다 성공했는지 실패했는지가 함께 들어 있습니다.
  • 뒤의 요청이 앞의 결과를 써야 하면(사용자 ID 로 그 사용자의 글을 요청) 함께 보낼 수 없고, 하나씩 await 합니다.

정리

섹션 제목: “정리”
결과를 받는 방법 에러 처리
콜백 끝난 뒤 실행할 함수를 넘김 단계마다 따로
Promise then catch
async·await await 로 값을 꺼냄 try...catch

세 방식 모두 시간이 걸리는 작업을 기다리는 동안 페이지를 멈추지 않으려는 방법입니다. 지금 쓰는 fetch, axios, React Query 는 모두 Promise 를 돌려주므로, 코드에서는 주로 async 와 await 로 다룹니다.
