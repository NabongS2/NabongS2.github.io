fetch 와 axios

2026년 10월 13일 · 읽는 데 6분
nabong

시리즈API 데이터 다루기

  1. 동기와 비동기
  2. fetch 와 axios
  3. Zustand 와 React Query

CSR 글에서 CSR 은 브라우저가 빈 HTML 을 받은 뒤, JS 가 API 로 데이터를 받아 화면을 만든다고 했습니다. 이 글은 그 “API 로 데이터를 받는” 부분입니다. 브라우저 코드에서 서버로 요청을 보낼 때 쓰는 fetch 와 axios 가 어떻게 다르고, 각각 어떻게 사용하는지 보고자 합니다.

예시 코드의 await 와 Promise 는 동기와 비동기 글에서 정리했습니다.

HTTP 클라이언트

섹션 제목: “HTTP 클라이언트”

HTTP 클라이언트는 서버에 HTTP 요청을 보내고 응답을 받는 일을 하는 도구입니다. 주소창에 URL 을 입력하면 브라우저가 이 일을 하고, 코드 안에서는 HTTP 클라이언트 함수를 호출해서 같은 일을 합니다.

이 글의 예시는 블로그의 글(post) 목록을 돌려주는 서버 주소 /api/posts 를 씁니다. 요청과 응답은 이렇게 생겼습니다.

상태 코드의 뜻은 HTTP 상태 코드 글에 정리했습니다. 이 글에서는 2xx 는 성공, 4xx·5xx 는 실패라는 것만 알면 됩니다.

자바스크립트에서 쓰는 HTTP 클라이언트는 여러 가지입니다.

설명
fetch 브라우저와 Node.js 18 이상에 기본으로 있는 함수
axios 가장 많이 쓰는 HTTP 클라이언트 라이브러리
ky, ofetch 등 fetch 를 감싸서 axios 처럼 편하게 만든 라이브러리

이 글은 그중 fetch 와 axios 를 다룹니다.

fetch

섹션 제목: “fetch”

GET 요청

섹션 제목: “GET 요청”
  • res 는 response(응답)를 줄인 이름입니다. fetch(url) 은 응답을 받으면 응답 전체를 담은 Response 객체를 돌려줍니다. 상태 코드(res.status), 헤더(res.headers), 본문이 들어 있습니다.
  • 본문은 아직 읽지 않은 상태입니다. res.json() 을 호출하면 본문을 읽어 자바스크립트 값으로 바꿉니다. 본문을 읽는 데도 시간이 걸려서 res.json() 은 값을 바로 주지 않고 Promise 를 돌려주므로, await 로 기다려서 값을 받습니다.
  • posts 는 그렇게 꺼낸 본문, 즉 글 목록입니다.

응답 본문 읽기

섹션 제목: “응답 본문 읽기”

res 를 console.log 로 보면 이렇게 생겼습니다.

상태 코드와 헤더는 바로 읽을 수 있지만, 본문은 아직 내려받는 중일 수 있는 데이터 흐름(ReadableStream)입니다. res.json() 은 이 본문을 끝까지 읽고, 읽은 글자 '[{"id":1,"title":"첫 글"}]' 를 자바스크립트 값 [{ id: 1, title: '첫 글' }] 로 바꾸는 일을 한 번에 합니다.

본문 형식에 따라 읽는 함수가 다릅니다.

함수 돌려주는 값 쓰는 경우
res.json() 자바스크립트 객체·배열 JSON 응답
res.text() 문자열 HTML, 일반 텍스트
res.blob() 파일 데이터 이미지, 파일 내려받기

본문은 한 번만 읽을 수 있습니다. 읽고 나면 bodyUsed 가 true 가 되고, 다시 읽으려고 하면 에러가 납니다. 그래서 셋 중 하나만 호출합니다.

POST 요청

섹션 제목: “POST 요청”

데이터를 보낼 때는 두 번째 인자에 메서드, 헤더, 본문을 넣습니다.

  • body 에는 문자열을 넣어야 해서, 객체를 JSON.stringify 로 바꿉니다.
  • Content-Type 헤더로 본문이 JSON 이라는 것을 서버에 알립니다.

응답 확인

섹션 제목: “응답 확인”

fetch 는 서버가 응답을 돌려주기만 하면 성공으로 봅니다. 404 나 500 응답도 응답이기 때문에 에러를 던지지 않습니다. 그래서 상태 코드를 직접 확인합니다.

res.ok 는 상태 코드가 200~299 이면 true 입니다. res.status 에는 상태 코드 숫자가 들어 있습니다.

fetch 가 에러를 던지는 것은 응답을 받지 못했을 때입니다. 인터넷 연결이 끊겼거나, 서버 주소가 틀렸거나, CORS 오류로 브라우저가 응답을 막은 경우입니다.

axios

섹션 제목: “axios”

axios 는 fetch 처럼 기본으로 있지 않아서 패키지를 설치합니다.

GET 요청

섹션 제목: “GET 요청”

axios 의 res 도 응답 전체입니다. 응답 본문이 JSON 이면 axios 가 미리 읽어서 자바스크립트 값으로 바꿔 res.data 에 넣어 둡니다. 그래서 res.data 가 곧 글 목록이고, res.json() 을 따로 호출하지 않습니다.

POST 요청

섹션 제목: “POST 요청”

두 번째 인자로 객체를 넘기면 axios 가 JSON 문자열로 바꾸고 Content-Type: application/json 헤더도 붙입니다.

에러 처리

섹션 제목: “에러 처리”

axios 는 응답의 상태 코드가 2xx 가 아니면 에러를 던집니다. 그래서 실패 처리는 try...catch 한곳에서 합니다.

  • error.response 에는 서버가 돌려준 응답이 들어 있습니다. 응답을 받지 못한 경우에는 비어 있습니다.
  • axios.isAxiosError(error) 는 axios 가 만든 에러인지 확인합니다. TypeScript 에서 error.response 를 쓰려면 이 확인이 필요합니다.

fetch 와 비교

섹션 제목: “fetch 와 비교”
fetch axios
설치 필요 없음 패키지 설치
응답 본문 await res.json() 을 직접 호출 res.data 에 바로 들어 있음
보낼 데이터 JSON.stringify 와 Content-Type 을 직접 지정 객체를 그대로 넘김
4xx·5xx 응답 성공으로 처리. res.ok 로 직접 확인 에러를 던짐
공통 설정 요청마다 직접 지정 인스턴스로 한 번에 지정
요청·응답 가로채기 없음 인터셉터
시간 제한 AbortSignal.timeout() 을 직접 넘김 timeout 옵션

표의 아래쪽 세 줄이 axios 를 쓰는 주된 이유입니다. 이어서 봅니다.

axios 인스턴스

섹션 제목: “axios 인스턴스”

앱이 호출하는 API 는 대부분 같은 서버에 있고, 같은 헤더와 시간 제한을 씁니다. 이 설정을 요청마다 쓰지 않도록 axios.create 로 설정을 정해 둔 axios 를 하나 만듭니다. 이것을 인스턴스(instance)라고 합니다. 인스턴스는 “실제로 만들어진 하나”라는 뜻으로, 같은 axios 로 설정이 다른 인스턴스를 여러 개 만들 수 있습니다.

  • baseURL: 요청 경로 앞에 붙는 주소입니다. 개발 서버와 운영 서버의 주소가 다르면 이 값만 바꾸면 됩니다.
  • timeout: 응답을 기다리는 최대 시간(밀리초)입니다. 기본값은 0 이고, 0 은 제한 없이 기다린다는 뜻입니다. 짧게 잡으면 응답이 없는 서버를 빨리 포기할 수 있고, 너무 짧으면 오래 걸리는 정상 요청도 실패로 끝납니다.

서버가 둘이면 인스턴스도 둘을 만들어 각각 씁니다.

인터셉터

섹션 제목: “인터셉터”

인터셉터(interceptor)는 “중간에서 가로채는 것”이라는 뜻입니다. axios 에서는 인스턴스로 보내는 모든 요청이 나가기 전, 또는 모든 응답이 코드에 도착하기 전에 실행되는 함수입니다. 요청마다 반복하던 일을 한곳에 둡니다.

요청 인터셉터

섹션 제목: “요청 인터셉터”

로그인한 사용자의 토큰을 모든 요청의 헤더에 붙이는 예입니다.

config 는 이번 요청의 설정(주소, 헤더 등)입니다. 함수가 돌려준 config 로 요청이 나갑니다.

응답 인터셉터

섹션 제목: “응답 인터셉터”

로그인이 만료되어 401 응답이 오면 로그인 페이지로 보내는 예입니다.

  • 첫 번째 함수는 2xx 응답을, 두 번째 함수는 에러를 받습니다.
  • 두 번째 함수에서 Promise.reject(error) 를 돌려주면, 요청한 코드의 catch 에도 에러가 전달됩니다. 공통 처리는 인터셉터에서 하고, 화면마다 다른 처리는 각 catch 에서 합니다.

에러 알림 창을 한곳에서 띄우고 싶으면, 응답 인터셉터에서 에러 내용을 상태 관리 라이브러리의 스토어에 기록하고 화면 한 곳에서 그 값을 보여 줍니다.

성공 응답에서 본문만 돌려주도록 만들기도 합니다.

이렇게 하면 요청하는 곳마다 res.data 를 꺼내지 않아도 됩니다. 대신 이 인스턴스로 받은 값에는 상태 코드와 헤더가 없습니다.

정리

섹션 제목: “정리”
fetch axios
하는 일 서버에 HTTP 요청을 보내고 응답을 받음 같음
실패 판단 응답을 받으면 성공. 상태 코드는 직접 확인 2xx 가 아니면 에러
공통 설정 없음 인스턴스(axios.create)
공통 처리 없음 인터셉터

요청이 몇 군데뿐이고 공통 설정이 필요 없으면 fetch 만으로 충분합니다. 같은 서버에 요청하는 곳이 많고, 토큰이나 에러 처리를 한곳에 모으고 싶으면 axios 인스턴스와 인터셉터가 그 일을 줄여 줍니다. fetch 로 같은 구조를 직접 만들 수도 있고, ky 같은 라이브러리를 쓸 수도 있습니다.
