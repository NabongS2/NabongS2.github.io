터미널, 서버 구조부터 vi 까지

2026년 9월 22일 · 읽는 데 10분
nabong

서버에 SSH 로 접속하면 이런 줄이 표시됩니다.

이 줄에서 다음 명령을 입력하려면, 지금 서버의 어느 위치에 있는지와 서버 안의 파일이 어떻게 놓여 있는지를 알아야 합니다. 이 글은 서버에 접속해 파일을 찾고 다루는 데 필요한 기본 개념과 명령을 알아보려고 합니다.

명령어 이름 옆에는 어떤 영어 단어에서 왔는지 함께 적었습니다. 예를 들어 rm 은 remove, pwd 는 print working directory 의 줄임말입니다.

서버

섹션 제목: “서버”

서버는 다른 컴퓨터가 네트워크로 접속해 사용하는 컴퓨터입니다. OS 가 설치되어 있고 프로그램이 실행된다는 점은 PC 와 같지만, 보통 모니터와 키보드를 연결하지 않고 다른 컴퓨터에서 원격으로 접속해 다룹니다.

SSH 접속

섹션 제목: “SSH 접속”

셸(shell)은 사용자가 입력한 명령을 읽어 실행하고 결과를 보여 주는 프로그램입니다. 터미널에서 명령을 입력하는 곳이 셸입니다.

ssh 는 secure shell, 암호화된 셸이라는 뜻입니다. 이 명령은 서버에서 셸을 하나 실행하고, 그 입력과 출력을 암호화된 연결로 내 화면에 이어 줍니다. 그래서 ls 를 입력하면 서버의 파일 목록이 출력됩니다.

접속할 때 본인 확인은 두 가지 방식이 있습니다.

  • 비밀번호 — 계정의 비밀번호를 입력합니다
  • 키 — 미리 만들어 둔 키 한 쌍을 씁니다. 공개키를 서버에 등록해 두고 개인키는 접속하는 쪽에 둡니다

접속에 쓰는 프로그램과 파일을 주고받는 방법은 따로 정리했습니다.

SSH 세션과 프로세스 종료

섹션 제목: “SSH 세션과 프로세스 종료”

SSH 로 접속하면 세션이 하나 생깁니다. 세션은 접속해서 연결을 끊을 때까지의 한 번의 연결이고, 그동안 셸이 실행됩니다. 그 셸에서 실행한 프로그램은 셸에 딸린 프로세스가 됩니다.

창을 닫거나 노트북을 덮거나 네트워크가 끊기면 세션이 끝납니다. 이때 셸은 자기가 실행한 프로세스에 SIGHUP(hang up) 신호를 보내고, 이 신호를 받은 프로세스는 기본적으로 종료됩니다. 그래서 세션이 끝나면 그 세션에서 실행한 프로그램도 함께 종료됩니다.

로그를 보다가 창을 닫는 것은 문제가 없습니다. tail 이 종료되어도 로그 파일은 그대로이기 때문입니다. 문제는 이런 경우입니다.

그래서 오래 실행해야 하는 프로그램은 세션과 분리해 실행합니다. 도커 글에서 docker run -d 의 -d 를 “백그라운드로 실행한다” 고만 적었는데, 정확히는 detached, 곧 세션과 분리해 실행한다는 뜻입니다. 컨테이너는 Docker 가 관리하는 프로세스라 SSH 세션의 신호를 받지 않고, SSH 창을 닫아도 계속 실행됩니다.

현재 위치와 경로

섹션 제목: “현재 위치와 경로”

윈도우 탐색기는 주소 표시줄에 현재 경로를 보여 줍니다. 터미널에서는 셸이 지금 작업 중인 디렉터리(현재 위치)를 기억하고, 그 경로를 출력하는 명령이 따로 있습니다.

pwd 는 print working directory, 지금 작업 중인 디렉터리를 출력하라는 뜻입니다.

프롬프트 구성

섹션 제목: “프롬프트 구성”

프롬프트는 셸이 명령을 기다리며 커서 앞에 표시하는 줄입니다. 대부분의 서버는 프롬프트에 현재 위치를 함께 표시하므로, pwd 를 입력하지 않아도 위치를 알 수 있습니다.

부분 값 뜻
@ 앞 dev 로그인한 계정
@ 와 : 사이 server 접속한 서버 이름
: 뒤 /opt/myapp 현재 위치
끝 글자 $ 일반 계정이면 $, root 면 #

위치가 ~ 로 나오면 내 홈 디렉터리라는 뜻입니다. /home/dev 를 매번 적기 번거로워서 ~ 로 줄여 씁니다.

절대경로와 상대경로

섹션 제목: “절대경로와 상대경로”
쓰는 법 뜻
/opt/myapp/log 최상단 / 부터 적은 절대경로. 어디서 실행해도 같은 곳을 가리킵니다
log 또는 ./log 지금 있는 자리 기준의 상대경로. . 은 현재 폴더입니다
../config .. 은 한 단계 위. 위로 올라가서 config 로 들어갑니다
~/notes 내 홈 아래의 notes

스크립트에는 절대경로를 쓰는 편이 안전합니다. 어느 위치에서 실행되든 같은 곳을 가리켜야 하기 때문입니다.

디렉터리 구조

섹션 제목: “디렉터리 구조”

리눅스 배포판은 대부분 FHS(Filesystem Hierarchy Standard)라는 표준을 따라 디렉터리를 나눕니다. 그래서 서버가 달라도 같은 이름의 디렉터리에 같은 종류의 파일이 있습니다.

경로 무엇이 있나
/home/dev dev 계정의 홈. 로그인하면 여기에서 시작합니다
/etc 시스템 설정 파일이 모여 있습니다
/var/log 로그. /var 는 variable, 실행 중에 내용이 계속 바뀌는 파일이 들어갑니다
/opt optional, 나중에 따로 설치한 프로그램. 직접 만든 앱을 여기 두는 일이 많습니다
/usr 배포판이 설치한 프로그램. /usr/bin 에 명령어들이 들어 있습니다
/tmp 임시 파일. 배포판 설정에 따라 재부팅하거나 일정 시간이 지나면 지워집니다. 보관할 파일은 두지 않습니다

/ 는 트리의 최상단이고, /root 는 root 계정의 홈 디렉터리입니다. 이름이 닮았지만 다른 곳입니다.

pwd, ls, cd

섹션 제목: “pwd, ls, cd”
명령 이름의 뜻
ls list, 목록
cd change directory, 디렉터리를 바꾼다

ls 는 옵션과 같이 쓰는 일이 많습니다. 옵션도 약자입니다.

cd 에는 경로를 전부 적지 않고 이동하는 짧은 표기가 있습니다.

Tab 키와 방향키

섹션 제목: “Tab 키와 방향키”

명령어 표에는 안 나오지만 터미널에서 계속 쓰는 키가 둘 있습니다.

Tab 은 경로를 반쯤 입력하고 누르면 나머지를 채워 줍니다. 후보가 여럿일 때 두 번 누르면 목록이 나옵니다.

방향키 위를 누르면 직전에 입력한 명령이 다시 올라옵니다. 계속 누르면 그 앞의 명령들로 거슬러 갑니다. 긴 명령을 조금만 고쳐 다시 실행할 때 씁니다.

파일 생성·복사·이동·삭제

섹션 제목: “파일 생성·복사·이동·삭제”
명령 이름의 뜻 하는 일
mkdir make directory 폴더를 만듭니다
touch 건드린다 원래는 파일의 시각을 갱신하는 명령입니다. 없는 파일을 지정하면 빈 파일이 만들어져서, 그 부수 효과로 파일 생성에 씁니다
cp copy 복사
mv move 이동
rm remove 삭제

mv 하나로 이름 변경과 이동이 모두 됩니다. 파일을 가리키는 것은 “경로 + 이름” 이고, 그중 이름만 바꾸면 이름 변경, 경로를 바꾸면 이동입니다. 둘이 같은 동작이라 명령도 하나입니다.

rm 삭제 주의점

섹션 제목: “rm 삭제 주의점”

rm 은 휴지통으로 옮기지 않고, 삭제할지 묻는 확인도 없습니다. 엔터를 누르면 바로 삭제되고 되돌릴 수 없습니다.

스크립트에서 변수로 경로를 받아 지울 때는 지우기 전에 경로가 비어 있지 않은지 확인합니다.

변수 이름을 잘못 적거나 값이 채워지지 않으면 $DIR 이 빈 문자열이 되어, rm -rf $DIR/ 가 rm -rf / 로 실행될 수 있습니다. set -u 는 정의되지 않은 변수를 쓰면 스크립트를 멈추고, 둘째 줄은 값이 비어 있으면 삭제 전에 종료합니다.

파일 내용 확인

섹션 제목: “파일 내용 확인”
명령 쓰는 자리
cat 짧은 파일을 통째로
head 앞부분만
tail 뒷부분만
less 긴 파일을 한 화면씩 넘겨 가며

cat 은 catenate, 여러 파일을 이어붙여 출력하는 명령입니다. 파일 하나만 지정하면 그 파일이 출력되므로 내용 확인에 씁니다.

로그 파일에 cat 을 쓰면 수만 줄이 화면을 지나가 버립니다. 긴 파일은 less 나 tail 을 씁니다. less 안에서는 방향키로 오르내리고, /검색어 로 찾고, q 로 나옵니다.

vi

섹션 제목: “vi”

서버에서 파일을 고쳐야 할 때 씁니다. vi 는 visual 의 앞 두 글자입니다.

vi 는 모드가 셋입니다. 같은 키가 모드마다 다르게 동작하기 때문에, 지금 어느 모드인지 알고 있어야 합니다.

열면 명령 모드로 시작합니다. 여기서는 키 하나하나가 명령이라 글자가 써지지 않습니다. 이 상태에서 문장을 타이핑하면 각 글자가 명령으로 실행됩니다.

입력 시작

섹션 제목: “입력 시작”
키 이름의 뜻 하는 일
i insert 커서 위치에서 입력 시작
a append 커서 다음 칸에서 입력 시작
o open line 아래에 빈 줄을 만들고 입력 시작
Esc 입력을 마치고 명령 모드로

저장과 종료

섹션 제목: “저장과 종료”

: 을 누르면 맨 아래 줄에 콜론이 뜨고, 거기에 명령을 적습니다.

이름의 뜻
:w write 저장
:q quit 종료
:wq write + quit 저장하고 종료. 가장 많이 씁니다
:q! quit 강제 저장하지 않고 종료. 고친 내용을 버리고 나올 때 씁니다

명령 모드의 줄 편집

섹션 제목: “명령 모드의 줄 편집”
키 이름의 뜻 하는 일
dd delete 커서가 있는 줄을 잘라냅니다. 지워진 줄은 클립보드에 들어갑니다
yy yank 커서가 있는 줄을 복사
p put 잘라내거나 복사한 것을 커서 아래에 붙여넣기
P 대문자는 위에 붙여넣기
u undo 방금 한 것 취소
Ctrl+r redo 취소한 것 되돌리기

dd 가 d 두 번인 이유는, d 가 “지운다” 는 명령이고 뒤에 범위가 오기 때문입니다. d 를 한 번 더 누르면 범위가 “현재 줄” 이 됩니다. 앞에 숫자를 붙인 3dd 는 세 줄을 지웁니다. yy 도 같은 구조입니다.

지금 어느 모드인지 모르겠으면 Esc 를 두어 번 누릅니다. 어느 모드에 있었든 명령 모드로 돌아옵니다.

nano

섹션 제목: “nano”

Ubuntu 나 Debian 계열 서버에서 crontab -e 같은 명령을 실행하면 vi 가 아니라 nano 가 실행됩니다. 이 계열 배포판의 기본 편집기가 nano 이기 때문입니다.

nano 는 모드가 없습니다. 열면 바로 글자를 입력할 수 있고, 화면 아래에 단축키 목록이 표시됩니다.

화면 아래의 ^X Exit 에서 ^ 는 Ctrl 키를 뜻합니다. ^X 는 Ctrl+X 입니다.
Ctrl+O 저장 (write Out)
Ctrl+X 종료 (eXit)
Ctrl+K 줄 잘라내기
Ctrl+U 붙여넣기
Ctrl+W 검색 (Where is)
vi nano
설치 POSIX 표준에 들어 있어 최소 설치본에도 대부분 있습니다 배포판에 따라 없을 수 있습니다
모드 명령·입력·콜론 모드를 오갑니다 없습니다
단축키 외워서 씁니다 화면 아래에 표시됩니다

로그 확인과 파일 검색

섹션 제목: “로그 확인과 파일 검색”

실시간 로그 확인

섹션 제목: “실시간 로그 확인”
  • -f — follow. 파일 끝을 계속 읽다가 새 줄이 추가되면 바로 출력합니다
  • -n 100 — number, 마지막 100줄을 먼저 출력하고, 그 뒤로 추가되는 줄을 이어서 출력합니다
  • 나올 때는 Ctrl+C

도커 컨테이너의 로그를 볼 때도 docker logs -f -n 100 처럼 같은 뜻의 옵션을 씁니다.

옵션 글자가 겹쳐서 헷갈리는 게 하나 있습니다. tail -f 의 f 는 follow 지만 rm -f 의 f 는 force 입니다. 같은 글자가 명령마다 다른 뜻입니다.

파일 내용 검색

섹션 제목: “파일 내용 검색”

grep 은 globally search a regular expression and print, 전체에서 정규식으로 찾아 출력하라는 뜻입니다.

  • -r — recursive, 하위 폴더까지
  • -n — number, 몇 번째 줄인지 같이
  • -i — ignore case, 대소문자 무시
  • --include="*.log" — 특정 확장자만

파이프로 이어 쓰는 일도 많습니다.

| 는 앞 명령의 출력을 뒤 명령의 입력으로 넘깁니다. 위 명령은 마지막 1000줄 중 ERROR 가 들어간 줄만 출력합니다.

계정과 권한

섹션 제목: “계정과 권한”

리눅스에는 무엇이든 할 수 있는 계정이 하나 있습니다. root 입니다. 시스템 파일을 지우는 것도 막지 않습니다.

그래서 평소에는 root 로 일하지 않습니다. 일반 계정으로 들어와서 권한이 필요할 때만 빌려 씁니다. 실수가 번질 범위를 줄이려는 것입니다. 지금 어느 쪽인지는 프롬프트 끝 글자로 알 수 있습니다.

권한이 없는 파일을 고치려 하면 이렇게 막힙니다.

이때 sudo 로 그 한 줄만 root 권한으로 실행합니다. substitute user do, 다른 계정으로 실행하라는 뜻이고 기본값이 root 입니다.

root 로 로그인해서 계속 쓰면 모든 명령이 무제한이 됩니다. rm -rf 를 잘못 입력해도 막아 줄 것이 없습니다. sudo 를 쓰면 그 한 줄만 root 권한으로 실행되고 나머지는 일반 계정으로 남습니다.

파일 권한 구조

섹션 제목: “파일 권한 구조”

ls -l 의 맨 앞 열 글자가 권한입니다.

자리 -rw-r--r-- 에서 뜻
1 - 종류. - 는 파일, d 는 디렉터리, l 은 링크
2–4 rw- user, 소유자
5–7 r-- group, 같은 그룹에 속한 사람
8–10 r-- other, 그 밖의 모든 사람

권한은 세 글자씩 묶여 있습니다.

글자 이름의 뜻 파일에서 디렉터리에서
r read 내용을 읽을 수 있다 목록을 볼 수 있다
w write 내용을 고칠 수 있다 안에 파일을 만들거나 지울 수 있다
x execute 실행할 수 있다 그 폴더로 들어갈 수 있다

위 예시를 읽으면 app.yml 은 소유자 dev 만 고칠 수 있고 나머지는 읽기만 됩니다. config 폴더는 root 소유라서, dev 계정으로는 들어가서 볼 수는 있지만 안에 파일을 만들 수는 없습니다.

숫자로도 씁니다. r 을 4, w 를 2, x 를 1 로 두고 세 묶음을 각각 더한 값입니다.

숫자 글자 뜻
755 rwxr-xr-x 소유자는 다 되고, 나머지는 읽고 실행만. 실행 파일과 폴더에 흔합니다
644 rw-r--r-- 소유자만 고치고 나머지는 읽기만. umask 가 022 일 때 새로 만든 파일의 권한입니다
600 rw------- 소유자만 읽고 씁니다. 남이 보면 안 되는 파일

chmod

섹션 제목: “chmod”

change mode, 권한을 바꿉니다.

리눅스는 확장자로 실행 여부를 정하지 않습니다. 실행 권한이 있어야 ./docker_run.sh 로 실행됩니다. 없으면 bash docker_run.sh 처럼 bash 에게 넘겨 실행합니다.

둘째 줄은 SSH 개인키의 권한입니다. 권한이 열려 있으면 ssh 가 그 키를 쓰기를 거부합니다.

chown 과 도커 볼륨

섹션 제목: “chown 과 도커 볼륨”

change owner, 소유자를 바꿉니다.

컨테이너 안에서 root 로 실행되는 앱이 마운트한 호스트 폴더에 로그를 쓰면, 그 파일은 호스트에서도 root 소유로 생깁니다.

sudo 로 그때그때 처리할 수도 있지만, 컨테이너를 root 가 아닌 계정으로 실행하면 이 문제가 생기지 않습니다. 이미지에서 USER 로 실행 계정을 지정하면 파일이 처음부터 그 계정 소유로 생깁니다. 도커 글의 이미지 작성 항목에서 다룬 내용입니다.
