VPN

2026년 10월 28일 · 읽는 데 6분
nabong

시리즈네트워크 기초

  3. NAT 와 포트포워딩
  4. VPN
  5. DNS 와 도메인
  6. HTTPS 와 인증서

앞 글의 포트포워딩은 내부 서버의 포트를 인터넷에 열어서, 그 주소를 아는 누구나 접속을 시도할 수 있게 합니다. 밖에서 내부 서버를 써야 하는 사람이 정해져 있다면, 포트를 여는 대신 그 사람들만 내부 네트워크에 접속하게 할 수 있습니다. 이 글에서는 그 방법인 VPN 이 어떻게 동작하는지, 포트포워딩·SSH 터널과 무엇이 다른지 알아봅니다.

이 글의 예시에서 쓰는 주소는 다음과 같습니다.

이름 주소
집 공유기의 공인 IP 198.51.100.50
회사 VPN 서버의 공인 IP 203.0.113.10
회사 내부 서버 192.168.0.20
VPN 서버가 내 PC 에 할당하는 IP 10.8.0.5

VPN

섹션 제목: “VPN”

VPN(Virtual Private Network)은 인터넷을 지나는 연결 위에 암호화된 통로를 만들어, 외부의 PC 가 내부 네트워크에 연결된 것처럼 동작하게 하는 기술입니다.

VPN 에 접속하면 다음 두 가지 변화가 생깁니다.

변화 결과
내 PC 와 회사 VPN 서버 사이에 암호화된 통로가 생깁니다 그 사이의 인터넷 구간에서 제3자가 내용을 읽거나 바꿀 수 없습니다
VPN 서버가 내 PC 에 내부에서 쓰는 IP(10.8.0.5)를 하나 할당합니다 회사 내부 서버가 보기에 내 PC 는 내부 네트워크의 컴퓨터입니다

그래서 집에서도 ssh dev@192.168.0.20 처럼 사설 IP 로 회사 내부 서버에 접속할 수 있습니다. 내부 서버의 포트는 인터넷에 열려 있지 않습니다.

터널

섹션 제목: “터널”

암호화된 통로를 터널이라고 부릅니다. 터널은 네트워크 계층에서 본 캡슐화를 한 번 더 하는 방식으로 동작합니다.

내 PC 에서 내부 서버로 보내는 요청은 다음과 같이 두 겹이 됩니다.

겹 출발지 목적지 내용
안쪽 패킷 10.8.0.5 192.168.0.20:22 원래 보내려던 요청. 전체가 암호화됩니다
바깥 패킷 198.51.100.50 203.0.113.10 인터넷 구간을 지나기 위한 패킷. 안쪽 패킷을 담습니다
  1. 내 PC 의 VPN 프로그램이 안쪽 패킷을 암호화해 바깥 패킷에 담고, 회사 VPN 서버의 공인 IP 로 보냅니다.
  2. 인터넷의 라우터들은 바깥 패킷의 주소만 보고 전달합니다. 안쪽 내용은 암호화되어 있어 읽을 수 없습니다.
  3. VPN 서버가 바깥 패킷에서 안쪽 패킷을 꺼내 복호화하고, 내부 네트워크의 192.168.0.20 으로 보냅니다.
  4. 응답은 같은 경로를 반대 방향으로 거쳐 돌아옵니다.

내부 서버는 요청이 10.8.0.5 에서 온 것으로 판단합니다. 내 집의 공인 IP 는 VPN 서버까지만 보입니다.

포트포워딩과의 차이

섹션 제목: “포트포워딩과의 차이”

포트포워딩과 VPN 은 모두 외부에서 내부 서버에 접속하게 하는 방법입니다.

포트포워딩 VPN
방식 내부 서버의 포트 하나를 인터넷에 엽니다 외부 PC 를 내부 네트워크에 연결된 것처럼 만듭니다
접속을 시도할 수 있는 사람 공인 IP 와 포트를 아는 누구나 VPN 계정이 있는 사람만
접속할 수 있는 범위 연 포트 하나 VPN 에서 허용한 내부 네트워크
인터넷에 열리는 포트 서비스마다 하나씩 VPN 서버의 포트 하나
준비 공유기·방화벽 규칙 VPN 서버, 사용자마다 VPN 프로그램과 계정

포트포워딩은 공개 웹 서비스처럼 누구나 접속해야 하는 경우에 맞습니다. 정해진 사람만 내부 관리 화면, DB, SSH 를 써야 한다면 VPN 으로 접속하게 하고 각 서비스의 포트는 열지 않을 수 있습니다.

VPN 은 접속한 사람에게 내부 네트워크 전체에 접속을 허용할 수 있다는 점도 함께 고려해야 합니다. VPN 서버나 방화벽에서 VPN 사용자가 접속할 수 있는 내부 주소와 포트를 정해 둘 수 있습니다.

회사용 VPN 과 개인용 VPN 서비스

섹션 제목: “회사용 VPN 과 개인용 VPN 서비스”

같은 기술을 쓰지만 목적이 다릅니다.

회사용 VPN 개인용 VPN 서비스
목적 밖에서 회사 내부 네트워크에 접속 내 접속 위치를 가리고, 공용 Wi-Fi 구간을 암호화
터널의 끝 회사 VPN 서버. 그 뒤가 회사 내부 네트워크 VPN 업체의 서버. 그 뒤가 일반 인터넷
웹사이트가 보는 내 IP 회사의 공인 IP (전체 터널일 때) VPN 업체 서버의 IP

개인용 VPN 서비스는 터널이 VPN 업체 서버에서 끝나고, 거기서부터는 일반 인터넷으로 나갑니다. 그래서 내부 네트워크에 접속하는 기능은 없습니다. 또 VPN 업체 서버에서 암호화가 해제되므로, HTTPS 로 암호화하지 않은 내용은 VPN 업체가 볼 수 있습니다.

전체 터널과 분할 터널

섹션 제목: “전체 터널과 분할 터널”

VPN 에 접속한 뒤 어떤 트래픽을 터널로 보낼지는 VPN 설정에 따라 다릅니다.

전체 터널 분할 터널(split tunneling)
터널로 전송되는 트래픽 모든 트래픽 회사 내부 주소(192.168.0.x 등)로 가는 트래픽만
일반 웹사이트 접속 회사를 거쳐 나갑니다 집 인터넷으로 바로 나갑니다
장점 회사 방화벽·보안 정책이 모든 접속에 적용됩니다 회사 회선을 거치지 않아 일반 인터넷이 느려지지 않습니다
단점 모든 트래픽이 회사를 거쳐 느려질 수 있습니다 일반 인터넷 접속에는 회사 보안 정책이 적용되지 않습니다

VPN 에 접속하면 일반 인터넷까지 느려지는 경우는 전체 터널일 가능성이 있습니다. 어느 쪽인지는 아래 “연결 확인”의 경로 확인 명령으로 확인할 수 있습니다.

대표 방식

섹션 제목: “대표 방식”

VPN 은 터널을 만드는 방식(프로토콜)에 따라 나뉩니다.

방식 특징 기본 포트
OpenVPN TLS 로 암호화합니다. 오래 사용되어 지원하는 장비와 클라이언트가 많습니다 UDP 1194 (TCP 443 으로도 설정 가능)
WireGuard 설정과 코드가 짧고, 연결이 빠릅니다. Linux 커널에 포함되어 있습니다 UDP 51820
IPsec 인터넷 계층에서 동작하는 표준입니다. 회사 사무실끼리 연결하는 장비 간 VPN 에 많이 씁니다 UDP 500, 4500

회사에서 받는 VPN 프로그램(방화벽 업체의 클라이언트 등)도 안에서는 이 중 하나나 업체가 만든 방식으로 터널을 만듭니다. 사용자 입장에서는 접속 주소, 계정, 인증서나 설정 파일을 받아 연결하면 됩니다.

SSH 터널과의 비교

섹션 제목: “SSH 터널과의 비교”

Redis GUI 도구에서 쓴 SSH 터널도 암호화된 통로를 만듭니다. 다만 범위가 다릅니다.

이 명령은 내 PC 의 6379 포트로 보낸 요청을 SSH 연결을 통해 서버로 보내고, 서버에서 127.0.0.1:6379 로 전달합니다. SSH 로 접속할 수 있는 서버 하나를 통해, 지정한 포트 하나만 연결합니다.

SSH 터널 VPN
연결하는 범위 명령에 적은 포트 하나 내부 네트워크
필요한 것 SSH 로 접속할 수 있는 서버와 계정 VPN 서버와 VPN 계정
내 PC 가 받는 내부 IP 없음 있음 (10.8.0.5)
쓰는 곳 서버 하나의 DB, Redis 같은 포트에 잠깐 접속할 때 내부의 여러 서버와 서비스를 계속 써야 할 때

연결 확인

섹션 제목: “연결 확인”

VPN 에 접속한 뒤 다음 순서로 확인합니다.

확인 결과 뜻
VPN 어댑터와 IP 가 없음 VPN 연결 자체가 되지 않았습니다
IP 는 있는데 내부 주소 경로가 VPN 쪽이 아님 경로 설정 문제. VPN 설정의 분할 터널 주소 범위를 확인합니다
모든 주소(0.0.0.0) 경로가 VPN 쪽 전체 터널입니다
경로는 맞는데 접속되지 않음 VPN 서버나 방화벽에서 그 서버·포트 접속을 막았을 수 있습니다

집과 회사의 주소 대역이 겹칠 때

섹션 제목: “집과 회사의 주소 대역이 겹칠 때”

집 공유기와 회사 내부 네트워크가 둘 다 192.168.0.x 대역을 쓰면, VPN 에 접속해도 192.168.0.20 이 집 네트워크의 주소인지 회사의 주소인지 PC 가 구분하지 못합니다. 이때 요청이 VPN 이 아니라 집 네트워크로 나가서 회사 서버에 접속되지 않습니다.

route print 나 ip route 에서 같은 대역이 두 경로에 등록되어 있으면 이 경우입니다. 집 공유기의 내부 대역을 192.168.50.x 처럼 회사와 겹치지 않게 바꾸면 해결됩니다.

정리

섹션 제목: “정리”
작업 방법
정해진 사람만 밖에서 내부 네트워크 사용 VPN
누구나 접속하는 서비스 공개 포트포워딩
서버 하나의 포트 하나에 잠깐 접속 SSH 터널 ssh -L 내포트:대상주소:대상포트 계정@서버
VPN 이 연결됐는지 확인 ipconfig, ip addr 에서 VPN 어댑터와 IP 확인
어떤 주소가 VPN 으로 전송되는지 확인 route print, ip route
