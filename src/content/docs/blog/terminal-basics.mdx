서버에 SSH로 붙으면 이런 줄 하나가 뜹니다.

```
dev@server:~$
```

`ls` 와 `cd` 는 알고 있었는데 여기서부터 막혔습니다. 지금 어디에 있는 건지, 이 서버 안이 어떻게 생겼는지를 몰랐으니까요. 명령어를 더 외워도 풀리지 않는 종류의 막힘이었습니다.

그래서 명령어 목록보다 그 앞의 것부터 적습니다. 서버가 뭔지, 파일이 어디에 놓이는지, 그다음이 명령어입니다.

약자는 같이 풀어 뒀습니다. `rm` 이 remove 인 걸 알면 외울 게 하나 줄어듭니다.

## 서버가 뭔가

**화면과 키보드가 없는 컴퓨터입니다.** 책상 위 PC와 다른 점은 사실 그것뿐입니다. 전원이 들어와 있고 OS가 돌고 프로그램이 떠 있는데, 모니터가 안 달려 있습니다.

그래서 들어가는 방법이 따로 필요합니다.

### SSH 로 접속하기

```sh
ssh dev@192.168.0.10
```

`ssh` 는 **s**ecure **sh**ell, 암호화된 셸이라는 뜻입니다. 이 명령이 하는 일은 저쪽 컴퓨터에 셸 하나를 띄우고 그 입출력을 내 화면으로 끌어오는 것입니다. 그래서 `ls` 를 치면 저쪽 파일이 나옵니다.

접속할 때 본인 확인은 두 가지 방식이 있습니다.

- **비밀번호** — 계정의 비밀번호를 입력합니다
- **키** — 미리 만들어 둔 키 한 쌍을 씁니다. 공개키를 서버에 등록해 두고 개인키는 접속하는 쪽에 둡니다

접속에 쓰는 프로그램과 파일을 주고받는 방법은 [따로 정리했습니다](/blog/ssh-and-sftp/).

### 세션이 끊기면 프로그램도 죽는다

SSH로 붙으면 **세션**이 하나 생깁니다. 그 세션에서 실행한 프로그램은 세션에 매달려 있습니다. 창을 닫거나 노트북을 덮거나 네트워크가 끊기면 세션이 죽고, **매달려 있던 프로그램도 같이 죽습니다.**

로그를 보다가 창을 닫는 건 아무 문제가 없습니다. `tail` 이 죽어도 로그 파일은 그대로니까요. 문제는 이런 경우입니다.

```sh
java -jar myapp.jar      # 앱을 띄우고
# 창을 닫는다 → 앱도 같이 죽는다
```

그래서 오래 돌아야 하는 것은 세션에 매달지 않습니다. [도커 글](/blog/docker-basics/)에서 `docker run -d` 의 `-d` 를 "백그라운드로 띄운다" 고만 적었는데, 정확히는 **d**etached, 곧 **세션에 처음부터 매달지 않는다**는 뜻입니다. 그래서 컨테이너는 SSH 창을 닫아도 계속 돕니다.

## 현재 위치와 경로

윈도우 탐색기에는 경로가 늘 위에 떠 있습니다. 그래서 "내가 어디 있는지" 를 따로 물어볼 일이 없습니다. 터미널에는 그런 표시가 없어서, 그걸 묻는 명령이 따로 있습니다.

```sh
pwd
```

`pwd` 는 **p**rint **w**orking **d**irectory, 지금 작업 중인 디렉터리를 출력하라는 뜻입니다.

<ThemedImage name="terminal/filesystem-tree" alt="윈도우는 드라이브마다 트리가 따로 있고 리눅스는 슬래시 하나에서 모든 것이 갈라진다는 비교" />

### 프롬프트 읽기

사실 대부분의 경우 `pwd` 를 치지 않아도 됩니다. 커서 앞에 이미 적혀 있습니다.

```
dev@server:/opt/myapp$
└┬┘ └─┬──┘ └───┬────┘│
 │    │        │     └─ 일반 계정이면 $, root 면 #
 │    │        └─ 지금 있는 위치
 │    └─ 접속한 서버 이름
 └─ 로그인한 계정
```

위치가 `~` 로 나오면 내 홈 디렉터리라는 뜻입니다. `/home/dev` 를 매번 적기 번거로워서 `~` 로 줄여 씁니다.

### 절대경로와 상대경로

| 쓰는 법 | 뜻 |
| --- | --- |
| `/opt/myapp/log` | 최상단 `/` 부터 적은 **절대경로**. 어디서 실행해도 같은 곳을 가리킵니다 |
| `log` 또는 `./log` | 지금 있는 자리 기준의 **상대경로**. `.` 은 현재 폴더입니다 |
| `../config` | `..` 은 한 단계 위. 위로 올라가서 `config` 로 들어갑니다 |
| `~/notes` | 내 홈 아래의 `notes` |

스크립트에는 절대경로를 쓰는 편이 안전합니다. 어느 위치에서 실행되든 같은 곳을 가리켜야 하니까요.

## 디렉터리 구조

리눅스는 폴더 이름이 정해져 있습니다. 관례라서 서버가 달라도 대체로 같은 자리에 같은 것이 있습니다.

| 경로 | 무엇이 있나 |
| --- | --- |
| `/home/dev` | `dev` 계정의 홈. 로그인하면 여기에 떨어집니다 |
| `/etc` | 시스템 설정 파일이 모여 있습니다 |
| `/var/log` | 로그. `/var` 는 **var**iable, 돌아가면서 내용이 계속 변하는 것들이 들어갑니다 |
| `/opt` | **opt**ional, 나중에 따로 설치한 프로그램. 직접 만든 앱을 여기 두는 일이 많습니다 |
| `/usr` | 배포판이 깔아 준 프로그램. `/usr/bin` 에 명령어들이 들어 있습니다 |
| `/tmp` | 임시 파일. 재부팅하면 사라집니다. 중요한 것을 두면 안 됩니다 |

`/` 는 트리의 최상단이고, `/root` 는 root 계정의 홈 디렉터리입니다. 이름이 닮았지만 다른 곳입니다.

## pwd, ls, cd

```sh
pwd                  # 지금 어디
ls                   # 여기 뭐 있나
cd /opt/myapp        # 저기로 이동
```

| 명령 | 이름의 뜻 |
| --- | --- |
| `ls` | **l**i**s**t, 목록 |
| `cd` | **c**hange **d**irectory, 디렉터리를 바꾼다 |

`ls` 는 옵션과 같이 쓰는 일이 많습니다. 옵션도 약자입니다.

```sh
ls -l                # long, 한 줄에 하나씩 권한·크기·시각까지
ls -a                # all, 숨김 파일(.으로 시작하는 것)까지
ls -h                # human-readable, 크기를 1.2G 처럼
ls -lah              # 붙여 쓸 수 있습니다
```

`cd` 에는 자주 쓰는 지름길이 있습니다.

```sh
cd ..                # 한 단계 위로
cd ~                 # 내 홈으로. cd 만 쳐도 같습니다
cd -                 # 직전에 있던 곳으로. 두 폴더를 왕복할 때 편합니다
```

### Tab 키와 방향키

명령어 표에는 안 나오지만 터미널에서 계속 쓰는 키가 둘 있습니다.

**Tab** 은 경로를 반쯤 치고 누르면 나머지를 채워 줍니다. 후보가 여럿일 때 두 번 누르면 목록이 나옵니다.

**방향키 위**를 누르면 직전에 친 명령이 다시 올라옵니다. 계속 누르면 그 앞의 명령들로 거슬러 갑니다. 긴 명령을 조금만 고쳐 다시 실행할 때 씁니다.

## 파일 다루기

| 명령 | 이름의 뜻 | 하는 일 |
| --- | --- | --- |
| `mkdir` | **m**a**k**e **dir**ectory | 폴더를 만듭니다 |
| `touch` | 건드린다 | 원래는 파일의 시각을 갱신하는 명령입니다. 없는 파일을 지정하면 빈 파일이 만들어져서, 그 부수 효과로 파일 생성에 씁니다 |
| `cp` | **c**o**p**y | 복사 |
| `mv` | **m**o**v**e | 이동 |
| `rm` | **r**e**m**ove | 삭제 |

```sh
mkdir logs
mkdir -p a/b/c       # parents, 중간 폴더까지 한꺼번에

cp app.jar app.jar.bak
cp -r config config.bak   # recursive, 폴더는 -r 이 없으면 복사되지 않습니다

mv old.txt new.txt        # 이름 바꾸기
mv old.txt /tmp/          # 옮기기
```

`mv` 하나로 이름 변경과 이동이 모두 됩니다. 파일을 가리키는 것은 "경로 + 이름" 이고, 그중 이름만 바꾸면 이름 변경, 경로를 바꾸면 이동입니다. 둘이 같은 동작이라 명령도 하나입니다.

### rm 은 확인 창이 없습니다

휴지통도 없고 "정말 삭제하시겠습니까" 도 없습니다. 엔터를 누른 순간 끝입니다.

```sh
rm file.txt
rm -r logs/          # recursive, 폴더와 그 안을 전부
rm -rf logs/         # force, 물어보지도 않고
```

`-rf` 로 사고가 나는 방식은 대개 이렇습니다.

```sh
DIR=/opt/myapp/tmp
rm -rf $DIR/         # $DIR 이 비어 있으면 rm -rf / 가 됩니다
```

변수 이름을 잘못 적거나 스크립트에서 값이 안 채워지면 `$DIR` 이 빈 문자열이 되고, 남는 것은 `rm -rf /` 입니다. 그래서 스크립트에서는 `set -u` 로 정의되지 않은 변수를 오류로 만들고, 지우기 전에 경로가 비었는지 확인합니다.

```sh
set -euo pipefail
[ -n "${DIR:-}" ] || { echo "DIR 이 비었다"; exit 1; }
rm -rf "${DIR}"
```

## 파일 내용 보기

| 명령 | 쓰는 자리 |
| --- | --- |
| `cat` | 짧은 파일을 통째로 |
| `head` | 앞부분만 |
| `tail` | 뒷부분만 |
| `less` | 긴 파일을 한 화면씩 넘겨 가며 |

`cat` 은 **cat**enate, 여러 파일을 이어붙여 출력하는 명령입니다. 파일 하나만 주면 그 하나가 출력되니 내용 보기에 쓰입니다.

```sh
cat app.yml          # 짧은 설정 파일
head -n 20 big.log   # 앞 20줄
tail -n 100 big.log  # 뒤 100줄
less big.log         # 한 화면씩. q 로 나옵니다
```

로그 파일에 `cat` 을 쓰면 수만 줄이 화면을 지나가 버립니다. 긴 파일은 `less` 나 `tail` 을 씁니다. `less` 안에서는 방향키로 오르내리고, `/검색어` 로 찾고, `q` 로 나옵니다.

## vi

서버에서 파일을 고쳐야 할 때 씁니다. `vi` 는 **vi**sual 의 앞 두 글자입니다.

vi 는 **모드가 셋**입니다. 같은 키가 모드마다 다르게 동작하기 때문에, 지금 어느 모드인지 알고 있어야 합니다.

<ThemedImage name="terminal/vi-modes" alt="vi 의 명령 모드, 입력 모드, 콜론 모드 사이를 어떤 키로 오가는지 보여주는 상태도" />

열면 **명령 모드**로 시작합니다. 여기서는 키 하나하나가 명령이라 글자가 써지지 않습니다. 이 상태에서 문장을 타이핑하면 각 글자가 명령으로 실행됩니다.

### 입력 시작

| 키 | 이름의 뜻 | 하는 일 |
| --- | --- | --- |
| `i` | **i**nsert | 커서 위치에서 입력 시작 |
| `a` | **a**ppend | 커서 **다음** 칸에서 입력 시작 |
| `o` | **o**pen line | 아래에 빈 줄을 만들고 입력 시작 |
| `Esc` | | 입력을 마치고 명령 모드로 |

### 저장과 종료

`:` 을 누르면 맨 아래 줄에 콜론이 뜨고, 거기에 명령을 적습니다.

| | 이름의 뜻 | |
| --- | --- | --- |
| `:w` | **w**rite | 저장 |
| `:q` | **q**uit | 종료 |
| `:wq` | write + quit | 저장하고 종료. 가장 많이 씁니다 |
| `:q!` | quit 강제 | 저장하지 않고 나오기. 잘못 건드렸을 때 탈출용 |

### 줄 단위로 다루기 (명령 모드에서)

| 키 | 이름의 뜻 | 하는 일 |
| --- | --- | --- |
| `dd` | **d**elete | 커서가 있는 줄을 잘라냅니다. 지워진 줄은 클립보드에 들어갑니다 |
| `yy` | **y**ank | 커서가 있는 줄을 복사 |
| `p` | **p**ut | 잘라내거나 복사한 것을 커서 **아래**에 붙여넣기 |
| `P` | | 대문자는 **위**에 붙여넣기 |
| `u` | **u**ndo | 방금 한 것 취소 |
| `Ctrl+r` | **r**edo | 취소한 것 되돌리기 |

`dd` 가 `d` 두 번인 이유는, `d` 가 "지운다" 는 명령이고 뒤에 범위가 붙기 때문입니다. `d` + `d` 는 "한 줄", `d` + `3d` 는 "세 줄" 입니다. `yy` 도 같은 구조입니다.

지금 어느 모드인지 모르겠으면 `Esc` 를 두어 번 누릅니다. 어느 모드에 있었든 명령 모드로 돌아옵니다.

## nano

Ubuntu 나 Debian 계열 서버에서 `crontab -e` 같은 명령을 실행하면 vi 가 아니라 nano 가 뜹니다. 그쪽 계열의 기본 편집기라서 그렇습니다.

nano 는 **모드가 없습니다.** 열면 바로 타이핑이 되고, 화면 아래에 단축키가 늘 떠 있습니다. 그래서 배울 것도 거의 없습니다.

딱 하나 함정이 있습니다. 화면 아래의 `^X Exit` 에서 **`^` 는 Ctrl 을 뜻합니다.** 키보드에서 `^` 를 찾다가 헤매게 되는 지점입니다.

| | |
| --- | --- |
| `Ctrl+O` | 저장 (write **O**ut) |
| `Ctrl+X` | 종료 (e**X**it) |
| `Ctrl+K` | 줄 잘라내기 |
| `Ctrl+U` | 붙여넣기 |
| `Ctrl+W` | 검색 (**W**here is) |

서버에 확실히 있는 것은 `vi` 입니다. POSIX 표준에 들어 있어서 최소 설치본에도 남습니다. 그래서 무게는 vi 쪽에 두는 편이 낫습니다. 다만 nano 가 먼저 뜨는 서버도 많으니, `^` 가 Ctrl 이라는 것만 알아 두면 당황할 일이 줍니다.

## 로그 보기와 파일 찾기

서버에 접속해서 하는 일은 대개 이 둘입니다.

### 로그를 실시간으로 보기

```sh
tail -f -n 100 app.log
```

- `-f` — **f**ollow. 파일 끝에 붙어 있다가 새 줄이 쌓이면 바로 보여줍니다
- `-n 100` — **n**umber, 최근 100줄부터 보여주고 이어서 따라붙습니다
- 나올 때는 `Ctrl+C`

도커 컨테이너의 로그도 같은 옵션을 씁니다. `docker logs -f -n 100` 이 이것과 같은 모양인 게 우연이 아닙니다.

옵션 글자가 겹쳐서 헷갈리는 게 하나 있습니다. **`tail -f` 의 `f` 는 follow 지만 `rm -f` 의 `f` 는 force 입니다.** 같은 글자가 명령마다 다른 뜻입니다.

### 파일 안에서 찾기

```sh
grep -rn "ConnectException" /opt/myapp/log
```

`grep` 은 **g**lobally search a **r**egular **e**xpression and **p**rint, 전체에서 정규식으로 찾아 출력하라는 뜻입니다.

- `-r` — **r**ecursive, 하위 폴더까지
- `-n` — **n**umber, 몇 번째 줄인지 같이
- `-i` — **i**gnore case, 대소문자 무시
- `--include="*.log"` — 특정 확장자만

파이프로 이어 쓰는 일도 많습니다.

```sh
tail -n 1000 app.log | grep ERROR
```

`|` 는 앞 명령의 출력을 뒤 명령의 입력으로 넘깁니다. 위 명령은 "마지막 1000줄 중 ERROR 가 들어간 줄만" 입니다.

## 계정과 권한

리눅스에는 무엇이든 할 수 있는 계정이 하나 있습니다. `root` 입니다. 시스템 파일을 지우는 것도 막지 않습니다.

그래서 평소에는 root 로 일하지 않습니다. 일반 계정으로 들어와서 권한이 필요할 때만 빌려 씁니다. 실수가 번질 범위를 줄이려는 것입니다. 지금 어느 쪽인지는 프롬프트 끝 글자로 알 수 있습니다.

```
dev@server:~$      일반 계정
root@server:~#     root
```

권한이 없는 파일을 고치려 하면 이렇게 막힙니다.

```
-bash: /etc/hosts: Permission denied
```

이때 `sudo` 로 그 한 줄만 root 권한으로 실행합니다. **s**ubstitute **u**ser **do**, 다른 계정으로 실행하라는 뜻이고 기본값이 root 입니다.

```sh
sudo systemctl restart myapp
sudo vi /etc/hosts
```

root 로 로그인해서 계속 쓰면 모든 명령이 무제한이 됩니다. `rm -rf` 를 잘못 친 순간 막아 줄 것이 없습니다. `sudo` 를 쓰면 그 한 줄만 root 권한으로 돌고 나머지는 일반 계정으로 남습니다.

### 파일마다 권한이 세 묶음

`ls -l` 의 맨 앞 열 글자가 권한입니다.

```
-rw-r--r--  1 dev  dev   1.2K  app.yml
drwxr-xr-x  2 root root  4.0K  config
```

```
-rw-r--r--
│└┬┘└┬┘└┬┘
│ │  │  └─ other  그 밖의 모든 사람
│ │  └─ group  같은 그룹에 속한 사람
│ └─ user  소유자
└─ 종류. - 는 파일, d 는 디렉터리, l 은 링크
```

세 글자씩 묶여 있습니다.

| 글자 | 이름의 뜻 | 파일에서 | 디렉터리에서 |
| --- | --- | --- | --- |
| `r` | **r**ead | 내용을 읽을 수 있다 | 목록을 볼 수 있다 |
| `w` | **w**rite | 내용을 고칠 수 있다 | 안에 파일을 만들거나 지울 수 있다 |
| `x` | e**x**ecute | 실행할 수 있다 | 그 폴더로 들어갈 수 있다 |

위 예시를 읽으면 `app.yml` 은 소유자 `dev` 만 고칠 수 있고 나머지는 읽기만 됩니다. `config` 폴더는 `root` 소유라서, `dev` 계정으로는 들어가서 볼 수는 있지만 안에 파일을 만들 수는 없습니다.

숫자로도 씁니다. `r` 을 4, `w` 를 2, `x` 를 1로 두고 세 묶음을 각각 더한 값입니다.

| 숫자 | 글자 | 뜻 |
| --- | --- | --- |
| `755` | `rwxr-xr-x` | 소유자는 다 되고, 나머지는 읽고 실행만. 실행 파일과 폴더에 흔합니다 |
| `644` | `rw-r--r--` | 소유자만 고치고 나머지는 읽기만. 일반 파일의 기본값입니다 |
| `600` | `rw-------` | 소유자만 읽고 씁니다. 남이 보면 안 되는 파일 |

### chmod

**ch**ange **mod**e, 권한을 바꿉니다.

```sh
chmod +x docker_run.sh        # 실행 권한 붙이기
chmod 600 ~/.ssh/id_rsa       # 나만 읽게
```

첫 줄이 앞에서 말한 그 이야기입니다. 리눅스는 확장자로 실행 여부를 정하지 않습니다. 실행 권한이 붙어 있어야 `./docker_run.sh` 로 실행됩니다. 없으면 `bash docker_run.sh` 처럼 bash 에게 넘겨 실행합니다.

둘째 줄은 SSH 개인키의 권한입니다. 권한이 열려 있으면 **ssh 가 그 키를 쓰기를 거부합니다.**

```
Permissions 0644 for 'id_rsa' are too open.
```

### chown 과 도커 볼륨

**ch**ange **own**er, 소유자를 바꿉니다.

컨테이너 안에서 root 로 도는 앱이 마운트한 호스트 폴더에 로그를 쓰면, 그 파일은 **호스트에서도 root 소유**로 생깁니다.

```sh
ls -l /opt/myapp/log
# -rw-r--r-- 1 root root 2.1M myapp.log

rm /opt/myapp/log/myapp.log
# rm: cannot remove ...: Permission denied
```

`sudo` 로 그때그때 처리할 수도 있지만, 근본적인 해결은 컨테이너를 root 로 돌리지 않는 것입니다. 이미지에서 `USER` 로 계정을 내려 두면 파일이 처음부터 그 계정 소유로 생깁니다. [도커 글](/blog/docker-basics/)에 적은 "root 로 돌리지 않기" 가 여기로 이어집니다.
